# Decisions, time, and AI usage

Running log — see `.claude/rules/decisions-log.md`. One line per entry, newest at the bottom.

## Decisions

- 2026-10-22 — Native SwiftUI (iPhone + iPad) instead of web. Why: platform strength; brief allows any stack. "Desktop and mobile" interpreted as iPhone + iPad adaptive layout.
- 2026-10-22 — MVVM + Repository + DataSource, no Service layer. Why: one data source and one domain action; a Service would be pass-through. Alt: Service → Repository → DataSource (deferred until triggers in `architecture.md`).
- 2026-10-22 — Swinject container owned by one top-level `AppModule` (registers and resolves everything; router gets a `ViewModelFactoryProtocol`, never the container), protocol-typed dependencies, one router; no per-feature injection modules. Why: wiring lives in exactly one place, every dependency is swappable/fakeable, and a Service layer slots in later without rewiring. Cost: ~30 min + one SPM dependency for a 3-screen app. Alt: manual composition root + `.environment` (lighter). Container is App-owned, not a singleton, so tests can build their own.
- 2026-10-22 — Spec-driven with criteria IDs referenced by tests. Why: makes AI-assisted work verifiable and traceable. Alt: full Spec Kit (cut, too heavy for timebox).
- 2026-10-22 — Maestro for UI flows (4 smoke flows), Swift Testing for logic; no XCUITest. Why: readable YAML flows, faster to author.
- 2026-10-22 — Auction states follow OPENLANE Canada (Upcoming → Active → Sold / Pending – below floor / No sale / Purchased by you), 72 h duration, launch time anchored at the 60th-percentile start (~75 upcoming / ~89 active / ~36 ended). Upcoming lots accept bids, like OPENLANE pre-sale proxy bids — which also explains dataset bids on not-yet-started lots. Alt: real 45-min auctions (only 1–2 active at a time, weak demo); live+ended only over 6 days (drops a state buyers actually see). Closing/Pending negotiation phases not simulated.
- 2026-10-22 — Buy Now is a core action (Active lots only), ends the lot as "Purchased by you"; bids must stay below the Buy Now price. Why: real OPENLANE feature, 39 lots have a price, ~20–30 min of work. Alt: price-only (brief excludes checkout) — rejected because no payment is involved, just a state change.
- 2026-10-22 — "Floor price" used as the buyer-facing term for reserve. Why: OPENLANE vocabulary.
- 2026-10-22 — Bids in memory, reset on launch. Why: no backend; predictable demo. Alt: SwiftData (cut, time).
- 2026-10-22 — Floor (reserve) amount hidden, only met / not met / no floor shown. Why: mirrors real auctions; still transparent to the buyer.
- 2026-10-22 — Adaptive bid step = price base ($200 / $500 / $1,000 at $10k / $30k) × activity (quiet ½, active 1×, hot 2× by bid count). Why: live auctioneers drop the increment when interest stalls and price tiers are universal (Copart UK table); bid count is the only activity signal in the data. Alt: flat $500 (matches the data's $500 grid — every current bid is a $500 multiple), price-only tiers, or time-decay on silence (moved to Stretch).
- 2026-10-22 — Decoded JSON types are `…Dto` and stay in `Data/`; app types are `…Model` (`VehicleModel`, `BidModel`), mapped in the DataSource. Why: file/wire shape (snake_case, raw strings, timezone-less dates) stays out of Domain and UI; swapping to a real API only touches Dtos + mapping. Alt: one `Codable` `Vehicle` used everywhere (fewer types, but couples app to JSON shape).
- 2026-10-22 — Ended outcome when you are high bidder but the floor isn't met → "Pending – below floor", not "Purchased by you". Why: a winning bid below floor is not a sale; spec wording made precise.
- 2026-10-22 — No `nonisolated`: all types stay on the main actor (target default), value types and injected protocols are `Sendable`. Why: simpler mental model; decoding 200 records on main is negligible. Alt: `nonisolated` models/decoders (more annotations, no measurable gain).
- 2026-10-22 — DTO mapping fails loudly on unknown enum values / bad dates with field + lot (`VehicleMappingError`). Why: bad data surfaces as an error state, never a crash or silently dropped vehicle.
- 2026-10-22 — `AppModule` resolves through a `preconditionFailure` helper instead of force unwraps / `swiftlint:disable`. Why: lint stays clean; a missing registration still fails fast on first launch.
- 2026-10-22 — Removed the template XCUITest file; UI coverage comes from Maestro. Why: the template tests added ~80 s to every test run.
- 2026-10-22 — Inventory uses imitated cursor pagination (pages of 20, keyset cursor = last vehicle ID, ~350 ms simulated latency). Search/filter/sort run "server-side" in the repository against live state, then the page is cut; the ViewModel keeps loaded IDs and reads vehicles live so bids show instantly. Why: realistic API shape for a 200+ lot marketplace, and filtering client-side over partial pages would be wrong. Alt: offset paging (shifts when lots change state), load-all (no paging story).
- 2026-10-22 — App shell (router, `ViewModelFactoryProtocol`, shared formatters/badge/image) built before features so parallel feature work never edits shared files. Placeholder image URLs return SVG, which `AsyncImage` can't render; they're rewritten to PNG in the Dto mapping.
- 2026-10-22 — Bids and Buy Now are async with ~600 ms simulated latency, validated on arrival. Why: makes in-progress / no-double-submit states real and testable, like a network call would. Shared loading/error/page-status components live in `Shared/` so every screen shows waits the same way.
- 2026-10-22 — Data is a live feed, not a one-time load: the data source exposes `vehicleFeed()` as an `AsyncThrowingStream` (snapshot, then updates) like a socket, plus bid / Buy Now request methods; the repository caches the feed and fans out `AsyncStream`s that screens consume in `.task`. A `SimulatedAuctionDataSource` plays the server (holds lot state, validates bids, echoes updates, simulates other bidders every ~6 s). Why: auction data changes at any time; swapping to WebSocket + HTTP only replaces the data source. Alt: Combine publishers (more ceremony, cancellables), `@Observable` repository only (no contract for external changes).
- 2026-10-22 — Scope extended past the core after comparing 3 other local implementations of the challenge: "My bids" screen (MYBIDS) with launch demo positions, per-vehicle bid history from launch onward (HIST), Saved watchlist (SAVED), extra filters/sorts (LIST-8/9), in-memory image cache (UX-6). Why: buyer needs "where do I stand" once outbid exists; others shipped saved lists, condition sort, clean-title filter. Alt: recommended subset (MYBIDS + seed + clean title + condition sort) — I chose the full set. Rejected: inline "Your bids" strip in the inventory (duplicates MYBIDS; outbid badge on the toolbar entry covers visibility).
- 2026-10-22 — Bid history never invents pre-launch bids: dataset bids show as one "N earlier bids" row. Why: data has only `current_bid` + `bid_count`, no amounts/times.
- 2026-10-22 — Added a simulated CARFAX-style vehicle history report (REPORT), generated deterministically from the VIN and kept consistent with odometer, damage notes, title status, and province. Labelled "Simulated report — demo data", no CARFAX branding. Why: history reports are standard on OPENLANE Canada listings and build buyer trust; the dataset has none. Alt: link out to a real report (needs a paid API), or omit.
- 2026-10-22 — After reviewing Copart, IAA, and OPENLANE buyer features, added proxy/max bidding (PROXY, moved out of Stretch), a fee-inclusive total estimate (FEES), auto-save on bid (SAVED-5), and a global outbid banner (ALERT). Why: proxy bidding is standard at every major auction site and pairs with the simulated market; total cost and outbid alerts build buyer trust. Proxy runs in the simulated data source, as on a real server. Skipped: saved-search alerts (needs notifications), counter-offers below floor (Pending negotiation out of scope), keys / run & drive / ERV fields (not in the data — would be invented), transport estimate (no buyer location).
- 2026-10-22 — Fee table is invented (flat $300 / $500 / 2 % tiers + $99 doc fee), labelled as an estimate. Why: real auction fee schedules vary by site and membership; the point is showing the total, not exact fees.
- 2026-10-22 — Added OPENLANE auction mechanics to scope: anti-sniping (TIME-5, 2 min extension), seller counter-offers on below-floor lots you lead (NEGOTIATE, simulated midpoint counter), condition grade explainer (DETAIL-7). Why: the challenge is from OPENLANE; these are how their buyers actually win or lose lots. Parked in a new "Postponed" section with reasons: saved-search alerts, starting-bid-drop alerts, transport, inspections, checkout, arbitration, Copart/IAA lot fields (not in data), time-decay step, inline bids strip. Stretch section replaced by Postponed.
- 2026-10-22 — Repository is no longer `@Observable`; screens get data only from its `AsyncStream`s (snapshot changes are announced too, so a subscriber that starts before loading isn't missed). The outbid marker hides once a lot has ended — the outcome takes over. Status filter says "Live" to match the badge.
- 2026-10-22 — Switched UI testing from Maestro to native XCUITest. Why: the Maestro MCP couldn't reach the simulator (it lists each booted simulator twice, as simulator and as "real", and picks the unreachable one) and the fix needed manual intervention; XCUITest ships with Xcode, runs via plain `xcodebuild`, and reviewers need nothing extra installed. A `-market off|fast` launch argument makes flows deterministic or speeds up the live outbid test.
- 2026-10-22 — Visual check (simctl screenshots: iPad split view, dark mode, largest accessibility text): fixed the price line wrapping mid-number ("$28,50 / 0") in the narrow iPad sidebar and at large text — card and detail now put title / amount / bid count side by side when they fit, stacked otherwise, and never break the amount.
- 2026-10-22 — App icon drawn by a Pillow script (`Resources/scripts/generate_app_icon.py`, gavel on sound block, navy/amber) with light, dark and tinted variants. Why: reproducible, no design tool or licensed artwork. Alt: hand-made asset in Figma (cut, time).
- 2026-10-22 — Maestro flows (`.maestro/`: smoke, live outbid) kept in the repo as optional exploratory checks; XCUITest stays the UI suite of record. Why: quick to run and already written during visual checks. Alt: drop them (lose a cheap live-update demo).
- 2026-10-22 — Stretch: My bids (container-scoped ViewModel so the toolbar's outbid badge stays live while the screen is closed; regroups from the repository on every feed signal and on a 1 s tick for auction ends), outbid banner (queued, auto-dismiss 4 s; suppressed only while that lot's bid sheet is on screen and not on its success step — otherwise a fast outbid right after bidding would never be shown), fee estimate (shown even for an invalid amount so the buyer sees the cost while typing).
- 2026-10-22 — Stream buffers are unbounded. Two agents independently found that the 64-value buffer dropped early lots from the ~200-lot snapshot burst (the seeded My bids lots vanished). Values are small structs, so unbounded is safe; regression test added.
- 2026-10-22 — Live UI tests retry the review step: with the fast market a competing bid can land during review and correctly send the sheet back to editing (LIVE-3), which made one test fail ~1 in 15 runs. Verified with three consecutive full green runs.
- 2026-10-22 - Inventory countdowns use one shared clock instead of one timer per visible row, and pause visual countdown updates while the list is moving. Live bid updates continue during scrolling. Pagination now prefetches five rows before each page boundary. Why: timer-driven layout work and late page loading caused visible scroll hitches.
- 2026-10-22 — Outbid banner redesigned as a compact Liquid Glass card (icon, "Outbid", one-line title, "Now $X", capsule "Bid again"); the ✕ button was dropped because the banner auto-dismisses and still dismisses on swipe or via the VoiceOver action. Why: the old card was heavy and covered the photo. Alt: native local notifications (rejected: permission prompt, only useful when the app is backgrounded, which the simulated market isn't; flaky SpringBoard UI tests).
- 2026-10-22 — After Buy Now the detail header shows "Purchased for $X" and the floor counts as met (DETAIL-2 updated). Why: Buy Now only set `yourPurchasePrice`, so the header kept "Starting at … · Floor not met" and looked stale. Alt: have the data source also set `currentBid` to the Buy Now price (rejected: a purchase isn't a bid and would inflate bid counts and min-bid math).
- 2026-10-22 — My bids outbid badge uses the system toolbar `.badge(_:)` instead of an offset overlay. Why: the Liquid Glass toolbar button clipped the overlay after navigating back. Alt: padding the label to fit the overlay (cut: still fights the glass shape).
- 2026-10-22 — Toolbar `.badge()` is applied before the accessibility modifiers. Why: placed last it overrode the VoiceOver value with the bare count ("1" instead of "Outbid on 1"), failing MyBidsUITests. Alt: change the test to expect "1" (rejected, worse for VoiceOver).
- 2026-10-22 — Native iOS only, no desktop version. Why: the brief allows "web or mobile" on "the platform you choose"; the Minimum Bar's "desktop and mobile" dates from the web-only brief, so it maps to small vs. large screens (iPhone stack, iPad split view). "My Mac (Designed for iPad)" is available by default but untested. Alt: Mac Catalyst / macOS target (cut: out of scope, extra testing).
